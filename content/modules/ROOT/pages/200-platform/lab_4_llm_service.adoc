= Lab 1.4 — Deploy Qwen3.8 as Models-as-a-Service

With the operators running, create the *platform instances* (including the Models-as-a-Service control plane) and publish *Qwen3.8* through the MaaS gateway. Developers then consume one HTTPS endpoint with a subscription-bound API key — not a raw predictor Service.

[NOTE]
====
*Estimated time:* 15 minutes active + ~10 minutes for the cached model to load +
*Persona:* Platform Engineer +
*Fire and forget:* Trigger the applies, then move to Lab 1.5. The model is ready before the Developer module begins.
====

== Model Serving Architecture

image::model-serving-architecture.png[Model Serving Architecture, align="center"]

OpenShift AI 3.5 serves the model as an `LLMInferenceService`. Models-as-a-Service sits in front: one Gateway, API keys, and a token quota. Clients call `https://maas.<apps-domain>/...` with a `sk-oai-` key. OpenShift 4.22 already has Gateway API — do not install Service Mesh 3.

== Step 1: Create Platform Instances

This instantiates the serving control plane, Dev Spaces, GPU policies, and the MaaS gateway. One apply, then one configure script (Authorino TLS + dashboard GPU taints and MaaS UI flags).

[source,sh,role=execute]
----

bash deploy/instances/configure-platform.sh
----

[cols="1,2", options="header"]

| Object | Purpose

| `DataScienceCluster`

| `Gateway` (`maas-default-gateway`)
| One HTTPS front door: `https://maas.<apps-domain>/`

| `Kuadrant` + workshop Postgres

== Step 2: Publish Qwen3.8 to MaaS

This creates:

* The `llm-serving` namespace and 50 Gi model-cache PVC
* `LLMInferenceService/qwen3` — Red Hat vLLM CUDA 3.5.0 on the GPU node, attached to `maas-default-gateway`
* `MaaSModelRef` (catalog entry), `MaaSAuthPolicy` (who can call it), `MaaSSubscription` (token quota)

[source,sh,role=execute]

oc apply -k deploy/inference

=== Understanding the LLMInferenceService

[source,yaml]
----
spec:
  replicas: 1
  model:
    uri: hf://RedHatAI/Qwen3.8-27B-INT4
    name: qwen3                          # <1>
  storageInitializer:
    enabled: false                       # <2>
  router:
    gateway:
      refs:
        - name: maas-default-gateway     # <3>
          namespace: openshift-ingress
  template:
    containers:
      - name: main
        image: registry.redhat.io/rhaii/vllm-cuda-rhel9:3.5.0
        args:
          - --served-model-name=qwen3
          - --max-model-len=40960
          - --ssl-certfile=/var/run/kserve/tls/tls.crt   # <4>
----

<1> API model id stays `qwen3`; the display name is Qwen3.8
<2> Weights already live on PVC `qwen-model-cache` (`HF_HOME=/opt/models`). Skip the storage-initializer re-download.
<3> Required for MaaS: the HTTPRoute attaches to `maas-default-gateway`
<4> OpenShift AI 3.5 enables backend TLS by default; vLLM must present the KServe service-CA cert

The image is **Red Hat AI Inference** CUDA (`rhaii/vllm-cuda-rhel9:3.5.0`) — not community `vllm/vllm-openai`.

=== Wait for the model

The first cluster cold-start downloads ~18 GiB from Hugging Face. This workshop PVC is already populated, so vLLM mainly loads weights into GPU memory (~5–8 minutes).

[source,sh,role=execute]
----
oc wait llminferenceservice/qwen3 -n llm-serving \
  --for=jsonpath='{.status.conditions[?(@.type=="Ready")].status}'=True \
  --timeout=600s

oc get maasmodelref,maasauthpolicy,maassubscription -A
----

== Step 3: Mint the workshop API key

Inference uses **one** `sk-oai-` Bearer token (not an access key + secret). The script mints a key bound to `qwen3-workshop` (5 000 000 tokens / 24h) and stores it as `OPENAI_API_KEY` for every Dev Spaces workspace.

[source,sh,role=execute]
----
bash deploy/inference/mint-workshop-key.sh
----

Smoke-test the same URL OpenCode will call:

[source,sh,role=execute]
----
HOST="maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')"
KEY="$(oc get secret ai-provider-openai-api-key -n openshift-operators \
  -o jsonpath='{.data.OPENAI_API_KEY}' | base64 -d)"

curl -sS "https://${HOST}/llm-serving/qwen3/v1/chat/completions" \
  -H "Authorization: Bearer ${KEY}" \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3","messages":[{"role":"user","content":"Say MAAS_OK"}],"max_tokens":16,"chat_template_kwargs":{"enable_thinking":false}}'
----

You should see `"content"` containing `MAAS_OK`. Extra keys for curl or apps can also be created in the dashboard; they do not replace this Secret.
