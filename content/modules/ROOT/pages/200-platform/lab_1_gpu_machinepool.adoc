= Lab 1.1 — Deploy a GPU Machine Pool

Act 1 starts here. Add a GPU-backed machine pool to your ROSA cluster. This is the NVIDIA L40S that will run Qwen3.8 — the in-cluster model OpenCode will call this afternoon.

[NOTE]
====
*Estimated time:* 15 minutes (5 min active + ~10 min wait) +
*Persona:* Platform Engineer +
*Fire and forget:* Trigger this lab first, then move on. The GPU node will be ready by the time you need it.
====

[IMPORTANT]
====
GPU nodes are expensive. The `g6e.xlarge` instance (NVIDIA L40S, 48 GB VRAM) costs approximately $1.65/hr on AWS. The pool is fixed at one node for this workshop to keep costs predictable.
====

== Understanding ROSA Machine Pools

A *machine pool* is a group of worker nodes with a shared configuration (instance type, labels, taints). ROSA manages the lifecycle of these nodes — provisioning, replacing failed nodes — so you don't have to interact with AWS EC2 directly.

Key parameters for the GPU pool:

[cols="1,2", options="header"]
|===
| Parameter | Value & Rationale

| `--instance-type g6e.xlarge`
| 1× NVIDIA L40S (48 GB VRAM), enough for Qwen3.8-27B INT4

| `--replicas 1`
| Fixed single GPU node — sufficient for this workshop and keeps costs predictable

| `--taints nvidia.com/gpu=present:NoSchedule`
| Prevents non-GPU workloads (dev pods, build pods) from landing on expensive GPU nodes
|===

== Create the GPU Machine Pool

Use your ROSA cluster name (`rosa list clusters`) and an availability zone that already has a worker (`oc get nodes -L topology.kubernetes.io/zone`).

[source,sh,role=execute]
----
rosa create machine-pool \
  --cluster <cluster-name> \
  --name gpu \
  --replicas 1 \
  --instance-type g6e.xlarge \
  --availability-zone <availability-zone> \
  --taints 'nvidia.com/gpu=present:NoSchedule'
----

.Sample Output
[source,text,options=nowrap]
----
I: Machine pool 'gpu' created successfully on cluster '<cluster-name>'
I: To view all machine pools, run 'rosa list machinepools -c <cluster-name>'
----

[WARNING]
====
If AWS returns `InsufficientInstanceCapacity`, delete the pool and recreate it in another zone of the same region (`rosa delete machine-pool --cluster <cluster-name> --machinepool gpu`, then `rosa create machine-pool` with a different `--availability-zone`). GPU instance types are not available in every AZ at all times.
====

Start a background wait for the GPU node to become Ready. `oc wait` only works after the node *exists* — poll until the label appears, then wait for Ready. Continue to the next lab while it completes:

[source,sh,role=execute]
----
(
  until oc get node -l node.kubernetes.io/instance-type=g6e.xlarge \
      --no-headers 2>/dev/null | grep -q .; do
    sleep 10
  done
  oc wait node -l node.kubernetes.io/instance-type=g6e.xlarge \
    --for=condition=Ready --timeout=600s
) &
echo "GPU node wait started in background (PID $!)"
----
