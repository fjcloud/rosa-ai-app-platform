= Lab 1.4 — Hand the Keys

The GPU is warming Qwen3.8. Your job now is to hand the afternoon developer a *launch URL* and a 43-line runbook — not a wiki, not Ansible, not a tour of every Kustomize file.

The template is already on GitHub: https://github.com/fjcloud/go-app-template[fjcloud/go-app-template].

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Platform Engineer +
*Deliverable:* You have read `AGENTS.md`. You can paste the Dev Spaces URL to Act 2.
====

== What the developer actually gets

[cols="1,2", options="header"]
|===
| Path | Why it exists

| `AGENTS.md`
| The only runbook OpenCode reads. Generate `main.go` / `go.mod` / `Dockerfile`, then `git` / `gitpop` / `oc`.

| `devfile.yaml`
| Dev Spaces workspace. Installs gitpop. OpenCode is *not* in the template — the platform injects it.

| `deploy/` `pipeline/` `gitops/`
| Golden-path Kustomize. The model applies it; it must not rewrite it (except the Deployment `image:` at deploy time).
|===

There is no `scripts/` directory and no Ansible. Qwen3.8 follows `AGENTS.md`.

== Step 1: Read AGENTS.md

Clone only if you want it on disk. On a shared workshop cluster you can also open the file on GitHub. Either way, *read it* — it is short.

[source,sh,role=execute]
----
git clone --depth 1 https://github.com/fjcloud/go-app-template
cd go-app-template
wc -l AGENTS.md
cat AGENTS.md
----

You should see about 43 lines. Notice:

* *Files YOU must generate* — `main.go`, `go.mod`, `Dockerfile` with an exact two-stage template
* *Files already in the repository* — do not rewrite `deploy/`, `pipeline/`, `gitops/`, or `devfile.yaml`
* *Three deploy phases* — Git server → Tekton PipelineRun → Argo CD Application

[cols="1,2,2", options="header"]
|===
| Phase | What it does | Typical duration

| 1. Git
| `gitpop init` + commit + push to the personal Git server
| ~30s

| 2. Image
| `oc apply -k pipeline/base` and a Tekton `PipelineRun` (git-clone + buildah)
| 3–5 min

| 3. GitOps
| Point `image:` at the built image, `oc apply -k gitops/base`, create the Argo CD `Application`
| 2–3 min
|===

== Step 2: Confirm OpenCode is wired to MaaS

OpenCode is injected from the AI tool registry you applied in Lab 1.3. You are checking the platform, not the template.

[source,sh,role=execute]
----
CHE_NS=$(oc get checluster -A -o jsonpath='{.items[0].metadata.namespace}')

oc get configmap opencode-workspace-config -n "$CHE_NS" \
  -o jsonpath='{.data.opencode\.json}' | python3 -m json.tool
----

You should see `baseURL` at `https://maas.<apps-domain>/llm-serving/qwen3/v1`, provider/model *name* `Qwen3.8`, API id `qwen3`, and `limit.output: 8192`.

[NOTE]
====
If you are on the shared workshop cluster, `GIT_SERVER` in `devfile.yaml` already matches. Do not fork and sed unless you are adapting this template to another cluster.
====

== Step 3: Copy the developer launch URL

[source,sh,role=execute]
----
DEVSPACES_URL=$(oc get checluster -A -o jsonpath='{.items[0].status.cheURL}')
TEMPLATE_URL="https://github.com/fjcloud/go-app-template"

echo "============================================"
echo " Participant workspace URL:"
echo "  $DEVSPACES_URL/#$TEMPLATE_URL?ai-provider=opencodeai/opencode"
echo "============================================"
----

When a developer opens that URL, Dev Spaces clones the template, injects OpenCode, mounts `opencode.json`, installs gitpop, and opens VS Code in the browser. They talk to the model; `AGENTS.md` is the runbook.

[IMPORTANT]
====
Workspaces created from an older template still have Ansible scripts. Create a *new* workspace from the URL above — restarting an old workspace is not enough.
====
