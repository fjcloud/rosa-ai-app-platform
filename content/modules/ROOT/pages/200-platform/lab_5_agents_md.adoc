= Lab 1.4 — Hand the Keys

The GPU is warming Qwen3.8. Prepare a *Dev Spaces launch URL* and the project runbook for the developer in Act 2.

The template is already on GitHub: https://github.com/fjcloud/go-app-template[fjcloud/go-app-template].

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Platform Engineer +
*Deliverable:* You have read `AGENTS.md`. You can paste the Dev Spaces URL to Act 2.
====

== What the developer actually gets

[cols="1,2", options="header"]
|===
| Path | Why it exists

| `AGENTS.md`
| The project runbook for OpenCode. Generate `main.go` / `go.mod` / `Dockerfile`, then git, ephemeral Git, and `oc`.

| `opencode.json`
| Pins OpenCode to in-cluster Qwen3.8 via MaaS. The API key is `$OPENAI_API_KEY` (injected). The OpenCode *binary* is still injected by Dev Spaces.

| `devfile.yaml`
| Dev Spaces workspace. Installs the ephemeral Git client.

| `deploy/` `pipeline/` `gitops/`
| Golden-path Kustomize. The Deployment already names the internal Tekton image. The pipeline validates that image before building; the model keeps the scaffold intact.
|===

There is no `scripts/` directory and no Ansible. Qwen3.8 follows `AGENTS.md`.

== Step 1: Read AGENTS.md

Clone only if you want it on disk. On a shared workshop cluster you can also open the file on GitHub. Either way, *read it* — it is short.

[source,sh,role=execute]
----
git clone --depth 1 https://github.com/fjcloud/go-app-template "$HOME/rosa-app-template"
wc -l "$HOME/rosa-app-template/AGENTS.md"
cat "$HOME/rosa-app-template/AGENTS.md"
----

Focus on these sections:

* *Files YOU must generate* — `main.go`, `go.mod`, `Dockerfile` with an exact two-stage template
* *Files already in the repository* — do not rewrite `deploy/`, `pipeline/`, `gitops/`, `devfile.yaml`, or `opencode.json`
* *Three deploy phases* — ephemeral Git → Tekton image validation/build → Argo CD Application; the Deployment image is preconfigured
* *Namespaces* — `$\{APP_NAME}-build` and `$\{APP_NAME}-dev` only. Never namespace `default` for the app, Argo CD, or the Application.

[cols="1,2,2", options="header"]
|===
| Phase | What it does | Typical duration

| 1. Git
| Create a personal repo on ephemeral Git, commit, and push
| ~30s

| 2. Image
| `oc apply -k pipeline/base` and a Tekton `PipelineRun` (git-clone + buildah)
| 3–5 min

| 3. GitOps
| Verify the preconfigured image, then apply `gitops/base` and create the Argo CD `Application`
| 2–3 min
|===

== Step 2: Confirm OpenCode is wired to MaaS

OpenCode is injected from the AI tool registry you applied in Lab 1.3. The *binary* comes from the platform. The *model pin* is `opencode.json` in the template — that file wins over `~/.config/opencode`.

[source,sh,role=execute]
----
CHE_NS=$(oc get checluster -A -o jsonpath='{.items[0].metadata.namespace}')

oc get configmap opencode-workspace-config -n "$CHE_NS" \
  -o jsonpath='{.data.opencode\.json}' | python3 -m json.tool
----

You should see `baseURL` `{env:OPENAI_BASE_URL}` (mint + `configure-platform.sh` set that env to `https://maas.<apps-domain>/llm-serving/qwen3/v1`), provider/model *name* `Qwen3.8`, API id `qwen3`, `limit.context: 262144`, and `limit.output: 32768`.

[NOTE]
====
If you are on the shared workshop cluster, `devfile.yaml` points to the workshop’s external ephemeral Git service. Source is pushed there for Tekton to clone. A requirement to keep *all source code* inside your cluster would also require an internal Git service and an adapted template.
====

== Step 3: Copy the developer launch URL

[source,sh,role=execute]
----
DEVSPACES_URL=$(oc get checluster -A -o jsonpath='{.items[0].status.cheURL}')
if [[ -z "$DEVSPACES_URL" ]]; then
  DEVSPACES_URL="https://$(oc get route devspaces -n openshift-operators \
    -o jsonpath='{.spec.host}')"
fi
TEMPLATE_URL="https://github.com/fjcloud/go-app-template"

echo "============================================"
echo " Participant workspace URL:"
echo "  $DEVSPACES_URL/#$TEMPLATE_URL?ai-provider=opencodeai/opencode"
echo "============================================"
----

When a developer opens that URL, Dev Spaces clones the template (including `opencode.json`), injects the OpenCode binary, installs the ephemeral Git client, and opens VS Code in the browser. They talk to Qwen3.8; `AGENTS.md` is the runbook.
