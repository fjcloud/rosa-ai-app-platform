= AI-Powered Developer Platform on ROSA

Welcome to the *AI-Powered Developer Platform on ROSA* workshop.

The story for today is a Monday at a company that wants its coding model to run inside its OpenShift cluster. This morning the platform team publishes Qwen3.8. This afternoon a developer ships an app with it. You wear both hats, then you look at the GPU and token bill.


== Who This Workshop Is For

[cols="1,1", options="header"]
|===
| Persona | Role in This Workshop

| *Platform Engineer* (morning)
| Provisions GPU capacity, installs operators, publishes Qwen3.8 behind a governed OpenAI-compatible API, and hands developers a short `AGENTS.md`.

| *Developer* (afternoon)
| Launches OpenShift Dev Spaces, talks to OpenCode backed by that in-cluster LLM, ships a real app through Tekton and Argo CD, then asks the same model to audit the manifests.
|===

== What You Will Build

image::architecture-overview.png[In-cluster coding agent on ROSA, align="center"]

The LLM writes the app. Qwen3.8 is a *platform* capability.

=== Act 1 — Platform
* A fixed-size *GPU machine pool* on ROSA — one NVIDIA L40S, no manual EC2
* *OpenShift AI* Models-as-a-Service serving *Qwen3.8-27B* (Red Hat AI INT4) behind one HTTPS front door and one `sk-oai-` key
* *OpenShift Dev Spaces* pointed at that gateway
* *AGENTS.md* — project instructions for OpenCode
* *OpenShift GitOps* (Argo CD) and *OpenShift Pipelines* (Tekton)

=== Act 2 — Developer
* A personal Git repository on *ephemeral Git* (workshop-scoped, no GitHub account)
* A *Fortune Cookie* Go app generated live by OpenCode + Qwen3.8
* Image build and GitOps deploy from git, ephemeral Git, and `oc` — no Ansible, no local Docker
* Platform rules (limits, probes, SCC, TLS) audited by the same model

=== Act 3 — The bill
* NVIDIA DCGM GPU metrics and vLLM token metrics in the same console
* MaaS subscription quota — how the platform team limits token consumption

== Learning Outcomes

After completing this workshop, you will understand:

* How ROSA managed machine pools give you GPU capacity without EC2 complexity
* How OpenShift AI (`LLMInferenceService` + Models-as-a-Service) is a governed OpenAI-compatible API on your cluster
* How `AGENTS.md` gives the coding agent platform conventions, backed by deployment checks
* How Dev Spaces + OpenCode is an AI-augmented inner loop with no laptop install
* How Tekton and Argo CD form a GitOps path from a single repository
* How GPU utilization and token counters help assess capacity while infrastructure is billed for provisioned time

== How to follow the labs

The morning/afternoon story represents two roles; you play both. Allow roughly half a day, including provisioning and image downloads. Timings are estimates.

Run Acts 0 and 1 in the *bastion terminal* from Cloud Terminal. In Act 2, switch to the *Dev Spaces terminal* in the browser IDE. Lab 3.1 names the terminal to use for each task. Paste shell blocks into a terminal and prompt blocks into OpenCode. Use `/exit` to leave OpenCode, or open another terminal for checkpoint commands.

The platform uses cluster-wide resources and the app uses fixed namespace names. Use one assigned cluster per participant. If several people share a cluster, the facilitator runs Act 1 once and assigns isolated app names, manifests and permissions before Act 2.

== Prerequisites

You will need:

* A web browser and an assigned RHDP ROSA environment with a ready cluster and a WeTTY terminal
* Cluster-admin access to that existing cluster
* ROSA and AWS permissions, regional quota and capacity for one On-Demand `g6e.xlarge` GPU worker
* At least five `m6a.xlarge` CPU workers, or equivalent allocatable capacity, in addition to the GPU
* This workshop repository (cloned at the end of Act 0) — not the Go app template
