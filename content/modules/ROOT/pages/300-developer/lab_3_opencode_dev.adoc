= Lab 2.2 — Prompt to Production

You have a Dev Space, an in-cluster LLM, and a 43-line `AGENTS.md`. Three OpenCode sessions take you from an empty tree to a live Fortune Cookie app, then through a real change — still no Ansible, no local Docker, no public LLM.

[NOTE]
====
*Estimated time:* 35 minutes +
*Persona:* Developer +
*What you build:* A Fortune Cookie web application in Go — generated, built with Tekton, deployed via your own Argo CD instance, then updated
====

[TIP]
====
OpenCode reads `AGENTS.md` before every prompt. You do not repeat platform rules — describe what you want. The LLM knows the Dockerfile template and the `git` / `oc` deploy phases.
====

== Session 1: Plan

The `plan` agent is read-only. It produces an implementation plan *without writing files*. Use it first so OpenCode internalizes `AGENTS.md`.

[source,text,role=execute]
----
/plan

I want a Fortune Cookie web application in Go.

The app serves:
- GET /   — an HTML page that displays a random fortune cookie message
            (hard-code at least 10 messages in a slice)
- GET /healthz — returns {"status":"ok"} for Kubernetes health probes

Read AGENTS.md and produce a complete implementation plan:
- File list and purpose of each file
- HTTP handler logic
- Dockerfile stages (follow the template in AGENTS.md exactly)
- Deploy steps from AGENTS.md (gitpop, Tekton PipelineRun, Argo CD)

Do not write any code yet. Only plan.
----

Review the plan. Adjust if needed. When satisfied, proceed to Session 2.

---

== Session 2: Build and Deploy

This session generates code, verifies the local build, then runs the deploy phases in `AGENTS.md`. Start a new session (`Ctrl+N`):

[source,text,role=execute]
----
/build

Implement the Fortune Cookie application following AGENTS.md strictly.

== Phase 1: Generate code

Generate these files:
1. main.go       — HTTP server on :8080, / (HTML fortune) and /healthz handlers
2. go.mod        — module: fortune-cookie, go 1.22
3. Dockerfile    — use the exact two-stage template from AGENTS.md
                   (ubi9/go-toolset builder → ubi9/ubi-minimal runtime, USER 1001)

After writing every file, run:
  CGO_ENABLED=0 go build -buildvcs=false -o /dev/null .

Fix any compile error before continuing. Show the build output.

== Phase 2: Deploy

Once the build succeeds, follow the three deploy phases in AGENTS.md in order
(gitpop + git push, Tekton PipelineRun, Argo CD Application).
Use git / gitpop / oc — do not create Ansible playbooks.

Wait for each phase to succeed before the next.
If a command fails, read the error and fix the root cause.

At the end, print:
- The app route URL
- The personal Argo CD console URL
----

OpenCode works through both phases. You will see the Dockerfile, the local Go build, then `gitpop` / `oc` from `AGENTS.md`.

=== Checkpoint — the app is live

[source,sh,role=execute]
----
APP_ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)
ARGOCD_ROUTE=$(oc get route argocd-server -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)

echo "================================================"
echo " App:    https://${APP_ROUTE}"
echo " ArgoCD: https://${ARGOCD_ROUTE}"
echo "================================================"

curl -sk https://${APP_ROUTE}/healthz
----

Expected:

[source,json]
----
{"status":"ok"}
----

Open both URLs in your browser:

* The app URL shows a random fortune cookie message
* The Argo CD console shows your `fortune-cookie` Application in *Synced / Healthy* — *your* Argo CD instance, scoped to your project

The Fortune Cookie process does *not* call Qwen3.8. The model wrote the code; the running app serves a slice of strings.

== Session 3: Ship a change

Close the GitOps loop: change the app, push, watch Tekton rebuild, roll the deployment. Still no hand-written `kubectl apply` for the app.

Start a new OpenCode session in `${PROJECT_SOURCE}`:

[source,text,role=execute]
----
/build

Add 10 more fortune cookie messages to the slice in main.go.
Make the HTML page display the fortune in a styled card with a cookie emoji 🥠.
After making the changes, verify the build:
  CGO_ENABLED=0 go build -buildvcs=false -o /dev/null .

Then ship it using the "Ship a later change" section in AGENTS.md:
git commit + push, a new Tekton PipelineRun, then
  oc rollout restart deployment/$APP_NAME -n ${APP_NAME}-dev
----

Wait for OpenCode to confirm the PipelineRun succeeded.

You can watch the build in the OpenShift console: *Pipelines → PipelineRuns* in the `fortune-cookie-build` namespace.

[source,sh,role=execute]
----
oc get application $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.status.sync.status} / {.status.health.status}' && echo

oc rollout status deployment/$APP_NAME -n ${APP_NAME}-dev --timeout=120s

ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev -o jsonpath='{.spec.host}')
echo "https://${ROUTE}"
curl -sk https://${ROUTE}/healthz
----

.Expected
[source,text,options=nowrap]
----
Synced / Healthy
----

Open the URL — you should see the cookie emoji 🥠 and the new fortunes.
