= Lab 2.1 — Launch Your Dev Space

Welcome to Act 2. You are now the *Developer* — first day using a coding model hosted on your platform. Everything you need — editor, terminal, OpenCode, Qwen3.8 on the cluster — is in the browser through *OpenShift Dev Spaces*. No laptop installation is required.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Developer +
*What you need:* The launch URL from Lab 1.4 and your cluster login
====

== What is OpenShift Dev Spaces?

OpenShift Dev Spaces provides *cloud-based developer workspaces* — VS Code-compatible IDEs that run as pods in the cluster. Key benefits:

* *Zero local setup:* the workspace comes pre-configured; just open a browser
* *Consistent environment:* every developer gets the same tools, versions, and configuration
* *In-cluster access:* your workspace calls Models-as-a-Service at `https://maas.<apps-domain>/...` with the injected `sk-oai-` key — same OpenAI API, governed quota
* *Persistent storage:* your work survives closing the browser, but remains tied to the lifetime of this RHDP environment. Export anything you want to keep before it expires

== Get the Dev Spaces URL

Use the URL you printed in Lab 1.4. It clones the Go app template (`go-app-template`) — not this workshop repo — and creates a workspace from its `devfile.yaml`:

[source,text,options=nowrap]
----
https://devspaces.apps.<cluster>/#https://github.com/fjcloud/go-app-template?ai-provider=opencodeai/opencode
----

[NOTE]
====
The `#<template-url>` suffix tells Dev Spaces to clone the template and create a workspace from its `devfile.yaml` automatically. OpenCode is injected by the platform (AI tool registry) and already talks to Qwen3.8. The workspace comes pre-loaded with `AGENTS.md`, `pipeline/`, `gitops/`, and `deploy/base/` — you only need to write the application code.
====

. Open that URL in your browser.

== Log In and Create Your Workspace

. You will be redirected to OpenShift SSO. Log in with the same cluster user you used for `oc`.

. If prompted, click *Continue* to trust the facilitator's template repository.

. On the Create Workspace page, confirm that **OpenCode** is selected under *AI Provider*. That selection injects the CLI at start; you do not install it yourself. You will see a progress screen:
+
[source,text]
----
Starting workspace...
Pulling universal developer image...
Injecting OpenCode...
Running postStart commands...
  ✓ Installing the ephemeral Git client
----
+
A cold first launch can take 5–10 minutes while the developer and editor images download. *Subsequent launches are faster* — the image is cached.

. When the workspace is ready, a VS Code-like editor opens in the browser. If it shows *Restricted Mode*, click *Manage* and trust this workspace to enable the terminal and development tools. You will see:
** A file explorer on the left
** A terminal at the bottom
** OpenCode available on `PATH` (injected by Dev Spaces, not by the template)
+
Do **not** sign in to GitHub Copilot. Che Code ships Copilot as a built-in; the platform disables it. Do not install Continue. Use OpenCode in the terminal to call the in-cluster Qwen model.

== Log the workspace terminal into OpenShift

Browser SSO does not authenticate `oc` in a new workspace. Open a workspace terminal, then use the OpenShift console user menu → *Copy login command*. Paste the resulting `oc login` command into that terminal using your assigned lab administrator. Keep the token out of OpenCode and Git.

[source,sh,role=execute]
----
oc whoami
oc auth can-i '*' '*' --all-namespaces
----

The check must return `yes` before deployment. These labs require administrator access to create namespaces and build permissions. A production platform would pre-create scoped developer permissions. If access is missing, ask the facilitator to prepare it.

== Verify OpenCode is Running

. Open a terminal in the workspace (*Terminal → New Terminal* or press kbd:[Ctrl+`]).

. Check that OpenCode is on `PATH` (injected) and that ephemeral Git is configured (`$GIT_SERVER`):
+
[source,sh,role=execute]
----
opencode --version && echo "GIT_SERVER=$GIT_SERVER"
----
+
.Sample Output
[source,text,options=nowrap]
----
1.x.x
GIT_SERVER=https://git.<workshop-domain>
----

. Verify OpenCode can reach Models-as-a-Service. `$OPENAI_BASE_URL` is already in the workspace. Take the gateway hostname from that URL:
+
[source,sh,role=execute]
----
oc wait llminferenceservice/qwen3 -n llm-serving \
  --for=condition=Ready --timeout=1200s

MAAS_HOST="${OPENAI_BASE_URL#https://}"
MAAS_HOST="${MAAS_HOST%%/*}"

curl --fail-with-body -sS --max-time 60 "https://${MAAS_HOST}/v1/models" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  | python3 -m json.tool
----
+
.Expected Output
[source,json,options=nowrap]
----
{
  "object": "list",
  "data": [
    {
      "id": "publishers/llm-serving/models/qwen3",
      "owned_by": "llm-serving/qwen3",
      "ready": true,
      "modelDetails": {
        "displayName": "Qwen3.8"
      }
    }
  ]
}
----
+
[TIP]
====
`$OPENAI_API_KEY` is the MaaS `sk-oai-` key the platform minted into Secret `ai-provider-openai-api-key`. `$OPENAI_BASE_URL` is the live MaaS path (`https://maas.<apps-domain>/llm-serving/qwen3/v1`) — `configure-platform.sh` binds the Gateway cert to this cluster. OpenCode calls that URL so the API model id stays `qwen3`.
====

. Start OpenCode:
+
[source,sh,role=execute]
----
opencode
----
+
The OpenCode terminal user interface (TUI) launches. It reads `AGENTS.md` and connects to the Qwen3.8 LLM automatically.
Two session modes are available: *plan* (read-only — no file writes) and *build* (writes files). Press kbd:[Tab] to switch from one to the other.
Use `/exit` to leave OpenCode when needed.

== Understanding the OpenCode Configuration

OpenCode reads **project** `opencode.json` first (it overrides the platform mount under `~/.config/opencode`). Verify the file in the template:

[source,sh,role=execute]
----
cat ${PROJECT_SOURCE}/opencode.json
----

Expected content:

[source,json]
----
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "qwen3": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Qwen3.8",
      "options": {
        "baseURL": "{env:OPENAI_BASE_URL}",
        "apiKey": "{env:OPENAI_API_KEY}",
        "chunkTimeout": 120000,
        "timeout": 600000
      },
      "models": {
        "qwen3": {
          "name": "Qwen3.8",
          "limit": {
            "context": 262144,
            "output": 32768
          }
        }
      }
    }
  },
  "model": "qwen3/qwen3",
  "autoupdate": false
}
----

OpenCode still reads `AGENTS.md` from the project directory at the start of every session. These instructions guide generation; the audit in Lab 2.3 checks the deployed result.

`limit.output` must stay well below `--max-model-len` (262144). The configured output allowance is 32 768 tokens within the 256K context window.
