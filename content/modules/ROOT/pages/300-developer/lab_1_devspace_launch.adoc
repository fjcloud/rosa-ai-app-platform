Welcome to Module 2. You are now the *Developer*. Everything you need — a code editor, a terminal, the OpenCode AI assistant, and a direct connection to the in-cluster Qwen3.8 LLM — is available in your browser through *OpenShift Dev Spaces*. No local installation required.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Developer +
*What you need:* Your OpenShift web console credentials (from Module 100)
====

== What is OpenShift Dev Spaces?

OpenShift Dev Spaces provides *cloud-based developer workspaces* — VS Code-compatible IDEs that run as pods in the cluster. Key benefits:

* *Zero local setup:* the workspace comes pre-configured; just open a browser
* *Consistent environment:* every developer gets the same tools, versions, and configuration
* *In-cluster access:* your workspace calls Models-as-a-Service at `https://maas.<apps-domain>/...` with the injected `sk-oai-` key — same OpenAI API, governed quota
* *Persistent storage:* your work is saved on a per-user PVC even if you close the browser

== Get the Dev Spaces URL

Your instructor has already prepared the launch URL for you.
It points at the platform template on GitHub and creates a workspace from its `devfile.yaml`:

[source,text,options=nowrap]
----
https://devspaces.apps.<cluster>/#https://github.com/fjcloud/go-app-template?ai-provider=opencodeai/opencode
----

[NOTE]
====
The `#<template-url>` suffix tells Dev Spaces to clone the template and create a workspace from its `devfile.yaml` automatically. OpenCode is injected by the platform (AI tool registry) and already talks to Qwen3.8. The workspace comes pre-loaded with `AGENTS.md`, `scripts/`, `pipeline/`, `gitops/`, and `deploy/base/` — you only need to write the application code.
====

. Open the URL your instructor shared in your browser.

Do **not** sign in to GitHub Copilot. Che Code ships Copilot as a built-in; the platform disables it. The in-cluster model is Continue (editor) and OpenCode (terminal agent).

== Verify OpenCode is Running

. Open a terminal in the workspace (*Terminal → New Terminal* or press kbd:[Ctrl+`]).

. Check that OpenCode is on `PATH` (injected) and that gitpop and Ansible were installed by `postStart`:
+
[source,sh,role=execute]
----
opencode --version && gitpop --version 2>/dev/null || true && ansible --version | head -1
----
+
.Sample Output
[source,text,options=nowrap]
----
opencode 0.x.x
gitpop version x.x.x
ansible [core 2.x.x]
----

. Verify OpenCode can reach Models-as-a-Service:
+
[source,sh,role=execute]
----
curl -sS \
  "https://maas.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')/v1/models" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  | python3 -m json.tool
----
+
.Expected Output
[source,json,options=nowrap]
----
{
  "object": "list",
  "data": [
    {
      "id": "publishers/llm-serving/models/qwen3",
      "owned_by": "llm-serving/qwen3",
      "ready": true,
      "modelDetails": {
        "displayName": "Qwen3.8",
        "contextWindow": "40960"
      }
    }
  ]
}
----
+
[TIP]
====
`$OPENAI_API_KEY` is the MaaS `sk-oai-` key the platform minted into Secret `ai-provider-openai-api-key`. OpenCode calls the path-based URL `/llm-serving/qwen3/v1` so the API model id stays `qwen3`.
====

. Start OpenCode:
+
[source,sh,role=execute]
----
opencode
----
+
The OpenCode TUI (Terminal UI) launches. It reads `AGENTS.md` and connects to the Qwen3.8 LLM automatically.
Two built-in session modes are available via `/plan` and `/build` slash commands.
Press `q` to exit OpenCode when needed.

== Understanding the OpenCode Configuration

The platform mounts `opencode.json` into every workspace (not from the Git template). Verify it:

[source,sh,role=execute]
----
cat ~/.config/opencode/opencode.json
----

Expected content:

[source,json]
----
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "qwen3": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Qwen3.8",
      "options": {
        "baseURL": "https://maas.<apps-domain>/llm-serving/qwen3/v1",
        "apiKey": "{env:OPENAI_API_KEY}",
        "chunkTimeout": 120000,
        "timeout": 600000
      },
      "models": {
        "qwen3": {
          "name": "Qwen3.8",
          "limit": {
            "context": 40960,
            "output": 8192
          }
        }
      }
    }
  },
  "model": "qwen3/qwen3",
  "autoupdate": false
}
----

OpenCode still reads `AGENTS.md` from the project directory at the start of every session. That is how the Platform Engineer's rules are enforced.

`limit.output` must stay well below `--max-model-len` (40960). OpenCode's default 32 000 output tokens would overflow the vLLM context window.
