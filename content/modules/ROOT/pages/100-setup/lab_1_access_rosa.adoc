= Act 0 — Get in

Your RHDP environment already contains a ROSA cluster and a bastion. Open its browser terminal, log in to that cluster, and clone the workshop. RHDP has already configured the cluster's AWS Marketplace billing.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Platform Engineer +
*Blocking:* Act 1 needs OpenShift 4.22 or later, cluster-admin access, and at least five Ready `m6a.xlarge` CPU workers (or equivalent capacity), plus the GPU worker added in Lab 1.1. Lab 1.1 adds the GPU machine pool to this existing cluster.
====

== Open your environment

. Sign in to https://demo.redhat.com[Red Hat Demo Platform] and open your assigned environment.
. Use the *workshop ID, assigned email, and workshop password* supplied by your facilitator.
. Open https://fjcloud.github.io/cloud-terminal-pages/[Cloud Terminal], choose *AWS · AI developer platform on ROSA*, enter those details, and click *Open workshop*. The launcher retrieves your assigned Showroom URL automatically.

The guide opens beside the environment's existing WeTTY terminal. If the terminal stays blank or asks for a login, use *Open in new tab* and the access details from your environment. Closing the page disconnects the view; RHDP controls environment expiration.

== Check AWS and ROSA

The bastion already has AWS and ROSA credentials. Keep the RHDP Red Hat login: it belongs to the organization that owns this cluster and its billing association.

[source,sh,role=execute]
----
aws sts get-caller-identity --query Account --output text
rosa whoami
rosa list clusters
----

Use the *existing ROSA HCP cluster* supplied by your facilitator. Lab 1.1 reads its ID from your OpenShift login and reuses an existing worker subnet. Do not create a second cluster or change its billing account.

== Log in to OpenShift

First check whether your terminal is already logged in:

[source,sh,role=execute]
----
oc whoami
----

If it is not, open the cluster console using the URL and credentials in your RHDP environment details. Select your user menu, then *Copy login command*, and run that command in this terminal. The facilitator must provide an account with cluster-admin permissions for the platform labs.

If your ROSA environment's access instructions require creating its initial `cluster-admin` user, follow those instructions once for the existing cluster, then use the generated login command. Do not reset an existing participant's credentials.

[source,sh,role=execute]
----
oc whoami
oc get nodes
oc auth can-i '*' '*' --all-namespaces
oc whoami --show-console
----

The workers must be Ready and the permission check must return `yes`. If access or quota for the GPU pool is missing, ask your facilitator before Act 1.

== Clone the workshop

[source,sh,role=execute]
----
cd "$HOME"
git clone https://github.com/fjcloud/rosa-ai-app-platform.git
cd rosa-ai-app-platform
bash scripts/onboard.sh
----

Keep this directory for all later `oc apply -k deploy/...` commands. The check validates the existing login and worker readiness; it does not provision a cluster, create users, or alter billing.
