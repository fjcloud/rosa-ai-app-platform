= AI Developer Platform on ROSA

Cloud SSAs use this guide to prepare access and lead participants through the platform and developer roles. Start with an *existing ROSA cluster* from Red Hat Demo Platform. RHDP prepares the cluster, bastion, AWS credentials, Red Hat login, and Marketplace billing.

== Run the workshop

. Order a ROSA workshop environment on https://demo.redhat.com[Red Hat Demo Platform], wait until it is ready, and assign participant access.
. Open https://fjcloud.github.io/cloud-terminal-pages/[Cloud Terminal], choose *AWS · AI developer platform on ROSA*, and enter the *workshop ID, assigned email, and workshop password*.
. The launcher retrieves the assigned Showroom URL. Shared workshop links contain only the guide and workshop ID; each participant signs in separately.
. Follow Act 0 to log in with `oc`, clone this repository, and run `bash scripts/onboard.sh`.

The platform labs require an existing ROSA HCP cluster, cluster-admin access, OpenShift 4.22 or later, and AWS GPU quota. Allocate at least five `m6a.xlarge` CPU workers for the platform, in addition to the GPU worker. Lab 1.1 detects the connected cluster and reuses its worker subnet to create one GPU node. The workshop adds the GPU pool, platform operators, model serving, and developer tooling; it does not create the base cluster.

The facilitator can expand the default CPU pool before participants start:

[source,sh]
----
CLUSTER_ID=$(oc get infrastructure cluster -o jsonpath='{.status.infrastructureName}')
rosa edit machinepool workers --cluster "$CLUSTER_ID" --replicas 5
----

Wait for the new workers to become Ready, then run the onboarding check. Keep the GPU pool at one replica.

== Architecture

[source,text]
----
Dev Spaces / OpenCode ──> MaaS gateway ──> Qwen3.8 / vLLM / one L40S
          │ generates
          ▼
     Fortune Cookie ──> ephemeral Git ──> Tekton ──> Argo CD ──> HTTPS app
----

The model helps write the application; Fortune Cookie does not call it at runtime. Inference stays on ROSA. Source is pushed to the template’s external ephemeral Git service. On-Demand is the default; Spot launches were denied by the tested RHDP account’s organization policy.

Use one assigned cluster per participant. On a shared cluster, the facilitator prepares the platform once and isolates each app’s namespaces and access.

== Content

Instruction pages are in `content/modules/ROOT/pages`; Kubernetes manifests are in `deploy`. The content builds with Antora and is published on https://fjcloud.github.io/rosa-ai-app-platform/modules/index.html[GitHub Pages].

Provisioning an independent cluster remains available through https://github.com/fjcloud/rosa-quickstart[rosa-quickstart], outside the participant onboarding flow. Do not run it in an assigned RHDP environment that already has a cluster.
